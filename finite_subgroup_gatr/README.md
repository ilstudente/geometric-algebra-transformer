## 1. Overview

GATr achieves exact equivariance under the **continuous** Pin(3,0,1) group acting on 16-component PGA multivectors.  This package replaces that continuous equivariance with **exact or approximate** equivariance under a **finite** rotation subgroup G_f ⊂ SO(3), while keeping all of GATr's geometric primitives:

- Multivector hidden states in PGA G(3,0,1)
- Geometric product and equivariant join as bilinear operations
- Gated-GELU nonlinearities
- Equivariant layer normalisation

The motivation is to study the trade-off between the inductive bias imposed by exact equivariance and the expressive power unlocked by (controlled) equivariance violation.

## 2. Theoretical Background

### 2.1 Projective Geometric Algebra (PGA)

PGA G(3,0,1) is a 16-dimensional algebra generated by basis vectors e₀, e₁, e₂, e₃ with signature (+,+,+,0).  Its 16-dimensional multivector space is graded:

| Grade | Basis elements                          | Geometric meaning           |
|-------|-----------------------------------------|-----------------------------|
| 0     | 1                                       | scalar                      |
| 1     | e₁, e₂, e₃, e₀                         | (dual) planes               |
| 2     | e₁₂, e₁₃, e₂₃, e₀₁, e₀₂, e₀₃         | (dual) lines / translations |
| 3     | e₁₂₃, e₀₁₂, e₀₁₃, e₀₂₃               | points                      |
| 4     | e₀₁₂₃                                  | pseudoscalar                |

**Rotors** live in the even subalgebra spanned by {1, e₁₂, e₁₃, e₂₃}.  A rotor r corresponds to a unit quaternion q = (w, i, j, k) via GATr's convention:

```
mv[0]  = w,  mv[8]  = -k,  mv[9] = j,  mv[10] = -i
```

The **versor (sandwich) product** r·M·r̃ gives the group action on any multivector M, where r̃ is the reverse of r.

### 2.2 Finite symmetry groups

We work with finite subgroups G_f ⊂ SO(3):

| Group         | Order | Description                        |
|---------------|-------|------------------------------------|
| Z_n (cyclic)  | n     | n-fold rotations about z-axis      |
| T (tetrahedral)| 12   | Rotational symmetry of tetrahedron |
| O (octahedral)| 24    | Rotational symmetry of octahedron  |
| I (icosahedral)| 60   | Rotational symmetry of icosahedron |
| Grid×Rotation  | n×m   | Product group for spatial grids    |

Each group element g acts on the PGA multivector space via a 16×16 matrix A_g, precomputed from the versor product.  The token sequence x: [B, X, C, 16] represents one token per group element.

### 2.3 Group-equivariant convolution (GM-CNN)

Given a token sequence x: [B, X, C_in, 16], the **group-equivariant convolution** is:

```
out(x) = Σ_{g ∈ N_k} W_g · in(τ_g(x))
```

where:
- N_k is the **word-metric neighbourhood** of the identity (elements reachable in ≤ k generator steps on the Cayley graph)
- τ_g is a **right-shift** permutation of the token sequence (see §2.4)
- W_g: C_in → C_out is a **grade-aware equivariant linear map** (9-dimensional basis)

This operation is equivariant with respect to left-multiplication by any h ∈ G_f:

```
out(τ_h(x)) = τ_h(out(x))
```

### 2.4 Right-shift convolution and equivariance

**Critical design decision:** the shift must be a **right shift**, not a left shift.

Right shift by g:  `τ_g(x)[x] = x[x·g]`  (permutation perm[x] = mul_table[x, g])

Left shift by g:   `σ_g(x)[x] = x[g⁻¹·x]`  (permutation perm[x] = mul_table[g_inv, x])

For the convolution `out(x) = Σ_g W_g · in(τ_g(x))`, applying a global left-action h gives:

```
out(τ_h(x))[y] = Σ_g W_g · in(τ_g(τ_h(x)))[y]
               = Σ_g W_g · in(x[y·g·h])   ← using right-shift associativity
               = τ_h(out(x))[y]            ← same permutation appears
```

With **left shifts** the analogous computation would mix `g·h` with `h·g`, which are not equal for non-abelian groups — breaking equivariance.

Implementation: `perms[k, x] = backend.mul_table[x, g_k]` (column g_k of the multiplication table).

### 2.5 Approximate equivariance

The exact equivariant weight matrix W_GM lives in a 9-dimensional subspace of the full C_out × C_in weight space.  We support three **error modes**:

| Mode              | Weight matrix              | Equivariance |
|-------------------|----------------------------|--------------|
| `none`            | W = W_GM                   | Exact        |
| `low_rank`        | W = W_GM + U·Vᵀ  (rank r)  | Approximate  |
| `dense_penalized` | W = W_GM + E  (full)        | Approximate  |

The departure from equivariance can be measured in two ways:
- **Structural error**: ‖E‖_F / ‖W_GM‖_F
- **Behavioural error**: ‖out(τ_h(x)) − τ_h(out(x))‖ / ‖out(x)‖

Both are tracked during training as diagnostic metrics.

## 3. Architecture

### 3.1 Common building blocks

All variants share these primitives (from `gatr/`):

- `geometric_product(x, y)` — bilinear product, implemented via 16×16×16 kernel
- `equivariant_join(x, y, ref)` — grade-4 dual of outer product; `ref[14]` = e₁₂₃ component
- `equi_layer_norm(x)` — normalise so mean channel norm² = 1
- `EquiLinear(in_mv, out_mv)` — grade-aware equivariant linear map (9-basis)

New primitives (from `finite_subgroup_gatr/`):

- `GMTokenMixer` — group convolution over the token dimension
- `GeoMLP` — GP + join + gated-GELU feedforward
- `DiscreteMVAttention` — self-attention over the group token dimension

### 3.2 Variant A — GM-only

```
Input [B, X, C_in, 16]
  ↓  EquiLinear  →  [B, X, c_mv, 16]
  ↓  (repeat num_blocks times):
     EquiLayerNorm + GMTokenMixer  +  residual
     EquiLayerNorm + GeoMLP        +  residual
  ↓  EquiLinear  →  [B, X, C_out, 16]
```

Pure group-convolutional; no attention.  Fastest, most parameter-efficient.

### 3.3 Variant B — GM + attention

Each block contains **both** a GMTokenMixer and a DiscreteMVAttention layer (with shared GeoMLP):

```
GMTokenMixer  →  residual
DiscreteMVAttention  →  residual
GeoMLP  →  residual
```

Adds global mixing across the **group** token dimension on top of local group convolution.
Note: this attention still operates over the X = |G| group tokens of a **single** input entity.
It does not mix across different physical objects (see §5.3 and §6 for implications).

### 3.4 Variant C — axial split

For inputs with shape `[B, N_obj, N_time, X, C, 16]`, Variant C cycles through:

1. **SymmetryAxisGMBlock** — GM convolution over X (group axis)
2. **ObjectAxisMVAttentionBlock** — attention over N_obj
3. **SymmetryAxisGMBlock** — repeat
4. **TimeAxisMVAttentionBlock** — attention over N_time

This is the most expressive variant, designed for spatiotemporal problems.

## 4. Finite Symmetry Backends

class FiniteSymmetryBackend:

### 5.2 PGA action matrices

For each rotation matrix R ∈ SO(3), the 16×16 action matrix A_R is computed as follows:

1. Convert R to quaternion q = (w, x, y, z) via Shepperd's method.
2. Embed q into a PGA rotor r (even subalgebra) using GATr's convention:
   `r[0]=w, r[8]=-z, r[9]=y, r[10]=-x` (all other components zero).
3. For each basis multivector e_j (j = 0..15), compute:
   `A_R[:, j] = GP(GP(r, e_j), reverse(r))`
   using GATr's precomputed geometric product table.
4. The resulting matrix satisfies `A_R @ v` = group action on v for any multivector v.

This is implemented in `backends/rotation_backend.py:_compute_mv_action_matrix`.

**Role in the forward pass**

The 16×16 action matrices appear at exactly two points — the input and output boundaries of the network — and **nowhere else**:

| Stage | Where | Operation |
|-------|-------|-----------|
| **Lifting** (input) | `nbody_experiment.py` | `einsum("gij, bnj -> bngi", action_matrices, x_pga)` — applies all |G| rotations to the input, creating one token per group element |
| **Unlifting** (output) | `nbody_experiment.py` | `einsum("gij, bgcj -> bgci", inv_mats, x_out).mean(dim=1)` — applies inverse rotation to each output token before collapsing |
| **Inside the network** | — | **Not used.** No matrix multiplication on the 16-component axis at any layer. |

Inside the network the group structure enters only as **index permutations** derived from the multiplication table:

```python
# shifts.py — right shift by g_k: perm[x] = x * g_k = mul_table[x, g_k]
perms[k] = backend.mul_table[:, g_k]   # [X] integer indices

# token_mixer.py — gather tokens, then mix channels with a learned weight
x_shifted = x_mv[:, perm, :, :]               # reorder tokens — no 16×16 matrix
out_mv += einsum("oi, bxid -> bxod", W_k, x_shifted)  # W_k: [C_out, C_in], channels only
```

The learned weights `W_k` operate only on the channel dimension `C`; the 16 PGA components are carried passively through the token sequence. The geometric content of a multivector is never modified by the GM convolution itself — only the channel mixing and token ordering change.

**Summary:** the structured group matrices encode the group action once (at lifting) and once in reverse (at unlifting). Everything in between is combinatorial: the multiplication table tells the mixer which token to read from, and the equivariant linear map assembles an output from those reordered tokens, grade by grade.

### 5.3 GM token mixer and the per-entity processing limitation

**Important:** in the n-body experiment wrapper (`experiments/nbody_experiment.py`), N_obj particles are folded into the batch dimension before the network runs:

```python
x_flat = x_lifted.reshape(B * N_obj, X, C_mv, 16)   # particles → batch
x_out  = self.net(x_flat, None)                       # each particle processed independently
```

This means **all variants (A, B, C) process each particle in isolation**. The GMTokenMixer and DiscreteMVAttention only mix over the X = |G| group tokens belonging to a single particle. There is no inter-particle communication: particle i never sees particle j's features at any layer.

As a result the model functions as a per-particle symmetry-aware MLP, not a true interaction model. It can learn rotationally-structured per-particle dynamics (e.g. mapping initial position/velocity → future position under the group's inductive bias) but cannot model gravitational or other pairwise interactions.

For a true n-body interaction model, the N_obj axis must remain in the token sequence alongside the group axis, with some form of cross-particle mixing (e.g. attention over the joint `[N_obj × X]` token set, or a separate inter-particle attention pass as in Variant C's object axis block).

---

`GMTokenMixer` in `gm/token_mixer.py`:

```python
class GMTokenMixer(nn.Module):
    def __init__(self, backend, c_mv, c_s, neighborhood_radius, error_mode, error_rank):
        ...
        # Precompute right-shift permutations for all K neighbourhood elements
        # perms[k, x] = x * g_k  (mul_table[:, g_k])
        self.perms  # [K, X]
        # K separate grade-aware linear maps (9-basis + optional error term)
        self.mv_weights  # GMWeightCollection of K EquivariantWeightMatrix objects

    def forward(self, x_mv, x_s=None):
        # out(x) = sum_k  W_k  *  x[perm_k]
        for k, perm in enumerate(self.perms):
            W = self.mv_weights[k].effective_weight()   # [C_out, C_in]
            x_shifted = x_mv[:, perm, :, :]
            out_mv += einsum("oi, bxid -> bxod", W, x_shifted)
```

**Grade-aware equivariant linear maps (9-basis):**
The 9 basis elements of Pin(3,0,1)-equivariant linear maps are grade projections (1↦1, 2↦2, ...) plus a few grade-swapping maps.  `effective_weight()` returns a C_out × C_in matrix in the full basis, assembled from 9 learned scalars.

### 5.4 GeoMLP

`GeoMLP` in `layers/geo_mlp.py`:

```
x_mv [B, X, C, 16]
  ├─ GP branch: EquiLinear → x_left; EquiLinear → x_right; geometric_product(x_left, x_right)
  └─ join branch: EquiLinear → j_left; EquiLinear → j_right; equivariant_join(j_left, j_right, ref)
  concat [GP || join]: [B, X, 2C, 16]
  gate = EquiLinear(concat) → scalar component [B, X, 2C, 1] → gated_gelu
  EquiLinear(gated) → output [B, X, C_out, 16]
```

`construct_reference_multivector` averages the e₁₂₃ (grade-3) component of the input batch, passed as the `ref` argument to `equivariant_join`.

### 5.5 Discrete MV attention

`DiscreteMVAttention` in `layers/discrete_attention.py`:

Standard multi-head self-attention with PGA-compatible Q/K/V projections:
- Queries and keys produced by `EquiLinear` over the multivector dimension
- Attention logits computed from the **scalar component** (grade-0) of `geometric_product(Q, reverse(K))` — this is the inner product of rotors, naturally equivariant
- Values projected by `EquiLinear`

### 5.6 Equivariance metrics

`training/equivariance_metrics.py`:

```python
def equivariance_error(model, x_mv, num_samples=None, backend=None):
    """Behavioural equivariance error: mean over sampled group elements g of
       ||f(τ_g(x)) - τ_g(f(x))|| / ||f(x)||
    """

def structural_error(model):
    """Structural error: mean over all weight matrices of
       ||E|| / ||W_GM||  where E = W - W_GM is the non-equivariant component
    """
```

Both are computed during training and logged to MLflow / WandB.

## 6. Known Limitations and Open Issues

### 6.1 No inter-particle communication (n-body wrapper)

As described in §5.3, the current `NBodyFiniteSubgroupWrapper` folds particles into the batch dimension. All mixing happens within a single particle's |G| group tokens. To properly model n-body dynamics the wrapper needs to be redesigned so that particles and group elements are both present in the token sequence simultaneously.

Variant C (`variant_c_axial.py`) has the right skeleton for this: it cycles between a group-axis GM block and an object-axis attention block. The n-body wrapper should adopt this pattern rather than flattening N_obj into the batch.

### 6.2 Equivariant unlifting required for position prediction

The output of the network after group-pooling must use **equivariant unlifting**, not a plain mean:

```python
# Wrong — algebraically zero for full rotation groups:
x_pooled = x_out.mean(dim=1)

# Correct — apply g⁻¹ before averaging:
inv_mats = action_matrices.transpose(-1, -2)
x_pooled = torch.einsum("gij, bgcj -> bgci", inv_mats, x_out).mean(dim=1)
```

Plain group-pooling produces an invariant output. For full 3D rotation groups (octahedral, tetrahedral, icosahedral) this is algebraically zero for any 3D position, since the group acts irreducibly on R³ with no fixed directions. This fix is already applied in the current `NBodyFiniteSubgroupWrapper`.
